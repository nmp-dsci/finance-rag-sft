finance-rag-sft · Finance RAG retriever · plan · 2026-10-12 · nothing built or trained yet

Does fine-tuning put the golden passage in the top 10 more often? Score the base model first.

This repo fine-tunes BAAI/bge-base-en-v1.5 on finance question and passage pairs, following use case UC1 in s63, the fine-tuning playbook. The base model and the fine-tuned model are both scored with the same harness, on the same held-out questions and the same passage corpus. The question is whether more test questions end up with their golden passage in the top 10. The baseline (M2) is built and logged before any training starts. The project also gets its own viewer, built the way tau2-loop's and vidore-v3-loop's are, in its own colour: hue 15, the colour this page is shown in.

Separate or combined? As first drafted, every row is one retriever ranking alone. BM25 orders passages by keyword overlap. bge orders them by vector cosine similarity. Neither sees the other's list. BM25 was there only as a floor.

D10 adds the combination most RAG systems actually ship: a hybrid row that fuses the two rankings with reciprocal rank fusion (RRF). Each passage gets 1/(60 + rank in BM25) + 1/(60 + rank in bge), taken from each retriever's top 100, and the fused list is re-sorted. It is scored on the same top 10 by the same harness, so it is just another row.

It adds two questions an interviewer will ask. Does fine-tuning beat simply adding BM25 (base hybrid against tuned dense)? And is fine-tuning still worth it once BM25 is fused in (base hybrid against tuned hybrid)?

Network access: the dataset and the three models are downloaded from the Hub once and cached. Everything else stays on your Mac and the central MLflow at localhost:5000, unless D4 sends training to Modal.

The number: is the golden passage in the top 10?

For each test question, embed it, rank every passage in the corpus by cosine similarity, and check whether a golden passage lands in the top 10. That is the headline. The other numbers explain why it moved.

Headline · Recall@10

hits@10 / test questions

A hit means at least one golden passage is ranked 1st to 10th. Almost every question has exactly one golden passage, so this is the same as Hit@10 or accuracy@10. Reported as a count as well as a rate.

Supporting · nDCG@10, MRR@10, Recall@1 and @5

If the base model already finds most golden passages in the top 10, Recall@10 has little room to move. These numbers show whether fine-tuning pushes golden passages higher in the list, and they let us compare with Phil's nDCG@10.

Size · 768 dims and 64 dims

Matryoshka training makes the first 64 dimensions a usable embedding on their own. In the reference run, the tuned model at 64 dims beat the base model at 768, which means a 12× smaller index. We score both sizes.

How the two rows are produced

One frozen split feeds both paths. Both paths end in the same harness, so the only thing that differs is the model.

Training in a container, so the project can move

One image runs finrag train the same way on any machine with an NVIDIA GPU, and a second target ships the viewer. This follows s63 §5's "one container, run two ways". There is one catch on your Mac.

Docker on a Mac can't use the Mac's GPU. Containers run inside a Linux VM, and Apple's Metal (MPS) isn't passed through to it. Inside Docker, training runs on the CPU: your Docker VM has 10 CPUs and 8 GB. So the container is how the project moves to a CUDA machine. On the Mac, the same code and the same uv.lock run natively, so training can use the GPU.

What counts as a result, fixed before M3

These are written down before training so the result can't move them. If you want different thresholds, annotate this section.

Floor

At 768 dims, the tuned model's Recall@10 on test is above the base model's, and the exact McNemar p-value is below 0.05.

Target

The tuned model at 64 dims matches or beats the base model at 768 dims on Recall@10 and nDCG@10. That is the 12× smaller index claim.

Guardrail

FiQA2018 nDCG@10 drops by no more than 0.02. If it drops further, the write-up says the model got worse outside this dataset.

Either way

Report the counts: how many test questions the tuned model newly gets right and how many it newly gets wrong. With about 700 test questions, every question is worth about 0.14 points.

The two pieces of code that matter

Sketches, not run. The training imports follow s63's Sentence Transformers v6 sketch and will be checked against the installed version in M0.

src/finance_rag_sft/harness.py · scores any model the same way

def score(model, split, dim: int, k: int = 10) -> Scores:
    pids, passages = split.corpus_ids, split.corpus_text   # all 6,757
    qids, questions = split.test_ids, split.test_text
    golden = split.test_golden                             # {qid: {pid, ...}}

    c = model.encode(passages, batch_size=64, convert_to_numpy=True)[:, :dim]
    q = model.encode(questions, batch_size=64, convert_to_numpy=True)[:, :dim]
    c /= np.linalg.norm(c, axis=1, keepdims=True)          # re-normalise after
    q /= np.linalg.norm(q, axis=1, keepdims=True)          # truncating to dim

    order = np.argsort(-(q @ c.T), axis=1)                 # rank every passage
    rank = {qid: 1 + int(np.flatnonzero(np.isin(pids[o], list(golden[qid])))[0])
            for qid, o in zip(qids, order)}                # best golden rank, 1 = top
    hits = np.array(list(rank.values())) <= k
    return Scores(recall_at_10=hits.mean(), per_query=rank,
                  ndcg_at_10=ndcg(rank, k), mrr_at_10=mrr(rank, k))

src/finance_rag_sft/compare.py · the paired test

def mcnemar(base: dict[str, int], tuned: dict[str, int], k: int = 10):
    qids = sorted(base)                                    # same questions
    assert qids == sorted(tuned)
    fixed  = sum(base[q] > k >= tuned[q] for q in qids)     # tuned gains
    broken = sum(tuned[q] > k >= base[q] for q in qids)     # tuned loses
    p = scipy.stats.binomtest(fixed, fixed + broken, 0.5).pvalue
    return {"fixed": fixed, "broken": broken, "p_exact": p}

Keeping the comparison fair

Same harness, corpus, questions and query prompt for both modelsOnly the model weights change. The query prompt is empty, as in the reference run.
Split by passage, and test that nothing leaksNo golden passage from test appears in train. CI fails if one does.
Pick the checkpoint on val, and score test onceThe test split goes through the harness twice in total: once for base and once for the chosen checkpoint.
Use a paired test and report countsUse McNemar on the same questions, report how many questions were fixed and broken, and give a bootstrap interval for the change.
Check outside the datasetFiQA2018 shows whether the model got better at finance retrieval in general or only at this one filing.
One seed is an anecdoteIf the gain is close to the floor, retrain with seeds 1 and 2 and report all three.
